# Skill Selection Guide

Start with the user outcome, then add only the smallest specialised skill that changes the quality or safety of the result.

| Situation | Use |
| --- | --- |
| A long-lived architecture trade-off | `adr` |
| A broad or unclear change | `specification-and-planning` |
| A current external technical claim | `source-grounding` |
| Evidence, authority, or validation boundary | `engineering-evidence-policy` |
| A change needs review | `code-review` |
| The review is security-focused | `security-review` |
| A high-stakes decision needs challenge | `doubt-driven-review` |
| A third-party skill needs static intake review | `skill-intake-review` |
| Supplied trend, media, edit, QA, or learning evidence | the matching Iron Science domain skill |

Do not activate a skill merely because it exists in the collection.
