# Contributing

Contributions should be small, reviewable, and evidence-backed.

1. Do not add secrets, private data, credentials, internal project material, generated artifacts, or absolute local paths.
2. Preserve a skill's directory structure and the compatibility of its root `SKILL.md`.
3. Document provenance, immutable source revision, license, adaptation status, and required notices before adding third-party material.
4. Keep operational boundaries explicit. A planning or review skill must not silently gain execution authority.
5. Update `manifests/skills-manifest.json`, `manifests/provenance-manifest.md`, and relevant documentation with every approved change.

New third-party content requires a separate provenance and security review before inclusion.
